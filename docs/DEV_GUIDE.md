# 개발 가이드 (휴대폰으로 따라 하는 Claude Code 프롬프트 모음)

> 회색 상자(코드 블록)는 **길게 눌러 전체 복사 → 붙여넣기**만 하세요. 한 번에 프롬프트 하나만 올립니다.
> 규칙·검증 절차는 프롬프트에 다시 쓰지 않았어요. `CLAUDE.md`가 매번 자동으로 읽힙니다.

---

## 0. 시작 전 (한 번만)

1. **`CLAUDE.md`와 이 문서가 `main`에 들어 있어야 합니다.** Claude Code는 `main`을 복사해서 일하기 때문에, 합치기 전에는 못 봅니다. GitHub 저장소 첫 화면에 `CLAUDE.md`와 `docs/DEV_GUIDE.md`가 보이면 됩니다. 안 보이면 열려 있는 PR을 합치세요.
   GitHub(앱 또는 브라우저) → `jn5310/be-the-agent` → **Pull requests** → 그 PR → **Merge pull request** → **Confirm merge**
2. Claude 앱 → **Code** 탭에서 GitHub가 연결돼 있어야 해요(입시 서바이벌과 같은 계정이면 이미 됨). 저장소 목록에 `be-the-agent`가 없으면 github.com/apps/claude 에서 Install → 저장소 선택에 `be-the-agent` 포함.

## 1. 작업 1회 하는 법 (모든 프롬프트 공통)

1. Code 탭 → **새 작업** → 저장소 `be-the-agent`, 브랜치 `main`
2. 권한 모드는 **Accept edits**(또는 Auto)
3. 아래 프롬프트 **하나**를 통째로 복사 → 붙여넣기 → 전송
4. 일하는 동안 앱을 꺼도 됩니다. 시뮬레이션이 들어가면 30~60분 걸려요.
5. 끝나면 화면 위쪽 **+숫자 −숫자**를 누름 → **Create PR**
6. GitHub → **Pull requests** → 방금 PR → **Merge pull request** → **Confirm merge**
7. 1~2분 뒤 https://jn5310.github.io/be-the-agent/ 를 열어 확인. 옛 화면이 보이면 새로고침(캐시가 최대 10분).

**모델:** 규칙·밸런스를 바꾸는 작업은 **Opus**, 문서·글만 바꾸는 작업은 **Sonnet**으로 충분해요.

**문제가 생기면** 같은 작업 화면에 이렇게 보내세요(스크린샷도 같이):
```
문제가 있어. [어느 화면에서] [무엇을 눌렀더니] [어떻게 됐어]. 원래는 [이렇게 되길 원해]. 원인을 찾아서 고쳐줘.
```

## 2. 프롬프트 세트 (위에서부터 순서대로, 하나 끝나면 다음)

### P19. 재미 지표와 사람 같은 봇 (Opus 추천) — 규칙은 안 바꾸고 재기만
```
CLAUDE.md를 먼저 읽어. 그다음 docs/review/18-critique.md와, docs/review/17-review.md의 4장 첫 문단·6장만 읽어.
이번 작업: tools/sim.js에 "재미 지표"와 사람 같은 봇 더하기. 게임 규칙은 바꾸지 않는다(game.js는 한 줄도 고치지 마. 꼭 필요하면 이유만 적고 멈춰).
1) 새 봇 3개(--bot 옵션): human(제안은 동의 50% 이상이면 수락, 소식의 15%는 넘김, 면담은 할 일 줄에 뜰 때만), greedy(돈이 되는 답만 고름), skipper(소식 대부분을 넘김, 비율은 정해서 PR에 적기).
2) "재미 지표" 구역 9개: 진짜 고민이 있는 주, 뻔한 답 비율, 긴장 주(만족 35 미만이거나 다른 에이전시 접근이 있는 주), 후회(제안을 받아들이거나 거절한 뒤 26주 안에 선수를 잃은 비율. 정의가 애매하면 가장 단순하게 정해 PR에 적기), 놀람(꿈의 구단 이적·첫 국가대표, 시즌당), 새로움(처음 겪는 일, 시즌별), 반복(이미 본 문장 조합 비율), 유대 100 비율(시즌별), 애착(함께한 기간 중앙값). 정의는 17-review 4장 첫 문단·6장 방식 그대로.
3) 10시즌 점검 출력: 법인 자금 중앙값, 유대 100 비율, 재계약 누적 성공률.
4) AGENTS.md 8장에 새 지표 표(정의·측정 방법)만 더해. 목표 범위는 아직 정하지 마.
5) attentive·human·greedy·skipper 각 300판 × 10시즌을 돌려 봇별 표로 보고(백그라운드로).
완료 조건: node --check tools/sim.js 통과, git diff에 game.js 없음, 기존 지표 출력은 그대로.
```

### P20. AGENTS.md 줄이기 (Sonnet 가능) — 내용은 지우지 않고 옮기기만
```
CLAUDE.md를 먼저 읽어.
이번 작업: AGENTS.md(약 160KB) 줄이기. 내용은 지우지 말고 docs/HISTORY.md로 글자 그대로 옮기기만 해.
1) 3장 "단계 계획"(1~18단계 완료 기록 전체)을 옮기고, 3장 자리에는 "단계별 기록은 docs/HISTORY.md" 한 줄만 남겨.
2) 8장의 지난 단계별 결과·튜닝 기록은 18단계 결과·튜닝 하나만 남기고 나머지는 옮겨. 0장 "마지막 밸런스 검증" 항목의 "이전 기록" 문단들도 옮기고 마지막 1개만 남겨.
3) 장 번호는 그대로 둬(4~9장 번호 바꾸지 마). "3장 18단계" 같은 참조는 grep으로 찾아 docs/HISTORY.md로 고쳐(AGENTS.md, README.md, CLAUDE.md, .kiro/steering/*, game.js·tools/sim.js 주석).
4) .kiro/steering/session-handoff.md의 "시작할 때" 절차를 "AGENTS.md는 0장만 읽는다"로 고쳐.
완료 조건: AGENTS.md 90KB 이하, 줄어든 만큼 HISTORY.md가 늘었는지 wc로 확인해서 보고, 코드 변경 없음, node --check game.js tools/sim.js 통과.
```

### P21. 약속 보상이 유대 상한에서 헛도는 문제 (Opus 추천)
```
CLAUDE.md를 먼저 읽어. docs/review/18-critique.md의 "상 1"만 읽어.
이번 작업: 약속 보상이 유대 상한(100)에서 헛도는 문제 고치기.
1) 약속 버튼 글(game.js의 "약속한다" 선택지)이 늘 "지키면 유대 +6"이라고 하는 것을, 실제로 오르는 만큼만 보이게 고쳐(이미 100이면 유대 줄은 빼고 만족만). 지켰을 때 로그 문구도 같게.
2) 유대 90 이상인 선수가 약속을 지키면 유대 대신 평판 +1(gainRep 사용)을 주는 안으로 진행해. 수치는 TUNE에 두고 어겼을 때 벌은 그대로 둬.
3) 고치기 전과 비교해서 8장 지표를 보고해(node tools/sim.js --games 1000 --all, 백그라운드). 목표 밖으로 나가면 같은 PR에서 TUNE만 조정.
4) PR 본문에 다른 대안 2개(예: 소개 보너스, 이적 동의 보너스)를 "선택지 | 추천" 표로 적어.
완료 조건: 글·규칙 모두 한국어·영어 짝(L), 영어 화면에 한글 없음, 8장 지표 모두 목표 안.
```

## 3. 큰 변경은 2단계로 (설계 → 구현)

규칙이 크게 바뀌는 일은 만들기 전에 설계안을 먼저 보고 고릅니다. 아래 두 프롬프트의 `[   ]` 부분만 주제표에서 골라 채우세요.

| 주제 | 고치는 문제 (18-critique) | 짧은이름 | 크기 |
|---|---|---|---|
| 첫 시즌과 처음 실행 안내 (안내 시트, 첫 시즌 목표 3개) | 중 7 | first-season | S |
| 이적 제안 일부를 두 구단 묶음으로 | 상 3 | offer-bundle | M |
| 60세 은퇴 엔딩과 큰돈 쓸 곳 | 상 4 | retirement | L |

### T1. 설계안 만들기 (Opus 추천) — 코드 변경 없음
```
CLAUDE.md와 .kiro/steering/game-design.md를 먼저 읽어. docs/review/18-critique.md도 읽어.
이번 작업: [주제]의 설계안만 만들기. 코드(game.js·style.css·index.html·tools)는 한 줄도 바꾸지 마.
docs/design/[짧은이름].md 하나에 적어: ① 고치는 문제(18-critique 번호) ② 다른 게임에서 가져올 구조와 우리 게임에 맞게 바꿀 점(이름·문구는 가져오지 말 것) ③ 선수와의 관계에 생기는 순간 ④ 규칙과 TUNE 이름·수치 후보 ⑤ 화면(글로 그린 시안 2개) ⑥ 지표에 줄 영향 예상과 위험 ⑦ 이 설계가 틀렸을 수 있는 이유 ⑧ "선택지 | 추천" 표(추천은 하나).
완료 조건: 문서 하나만 추가됨.
```

### T2. 구현하기 (Opus 추천) — T1을 Merge한 뒤
```
CLAUDE.md를 먼저 읽어. docs/design/[짧은이름].md를 읽어.
이번 작업: 그 설계의 [추천안 / 내가 고른 안: ___ ]을 구현해.
세이브 구조가 바뀌면 SAVE_VERSION을 올리고 이전 버전 변환과 왕복 확인을 넣어. 새 글은 L(한국어, 영어)로. 새 화면 요소는 REQUIRED_IDS에. 규칙을 바꿨으니 node tools/sim.js --games 1000 --all(백그라운드)로 8장 지표와 P19의 재미 지표를 전후 비교해서 PR 본문에 적어. 목표 밖이면 같은 PR에서 TUNE만 조정.
완료 조건: CLAUDE.md의 작업 방식 전부, index.html ?v= 올림, AGENTS.md 0장 갱신.
```
